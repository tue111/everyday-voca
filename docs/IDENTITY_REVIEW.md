# 이름·생년월일 가입 및 복구 코드 제거 검토

작성: 2026-09-30. 검토만 수행했으며 가입, 로그인, 복구 기능은 변경하지 않았다.

## 결론

같은 브라우저에서 자동 로그인하는 기능은 이미 있다. 이름과 생년월일을 입력받는 것은 가능하지만, 이 둘만으로 기존 계정에 로그인하거나 기록을 복구하는 방식은 권장하지 않는다. 평소 자동 로그인과 기기를 바꿀 때 본인임을 확인하는 절차를 구분해야 한다.

## 현재 동작과 근거

- 이름은 표시용이며 같은 이름도 별개의 사용자 ID로 생성한다 (`server/service.ts`).
- 최초 가입 또는 복구 시 90일 유효한 무작위 세션을 발급한다. DB에는 세션과 복구 코드의 해시만 저장한다 (`server/service.ts`).
- 브라우저는 `voca_session` 쿠키를 보관하고 다음 접속에도 전송한다. 쿠키는 HttpOnly, SameSite=Lax이며 운영에서는 Secure를 적용한다. 접속할 때마다 90일로 갱신하는 방식은 아니다 (`server/http.ts`).
- 다른 브라우저, 새 기기, 쿠키 삭제, 세션 만료, 로그아웃 후에는 현재 복구 코드가 필요하다. 홈 화면에 추가했다고 다른 브라우저의 로그인 정보가 공유된다고 가정하면 안 된다.

## 이름과 생년월일의 한계

이름과 생년월일은 사용자를 찾는 정보일 수 있지만 계정 소유자임을 증명하는 비밀은 아니다. 같은 이름과 생일을 가진 사람이 존재하며, 지인이나 유출 자료로 다른 사람의 정보를 알 수 있다. 같은 값 입력 시 자동 로그인시키면 타인의 학습 기록과 알림 설정에 접근할 수 있다. 중복 조합 가입을 막아도 먼저 가입한 사람이 다른 사람의 접근을 가로막는 문제가 생긴다. 시도 횟수 제한만으로 해결되지 않는다.

OWASP는 생년월일 같은 보안 질문을 안전한 인증 수단으로 권장하지 않는다. [보안 질문 지침](https://cheatsheetseries.owasp.org/cheatsheets/Choosing_and_Using_Security_Questions_Cheat_Sheet.html), [인증 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html).

영어 학습 기능에 생년월일이 필요하지 않다면 수집하지 않는 편이 낫다. 추가 수집을 선택하면 목적, 보관 기간, 삭제 및 접근 통제도 정해야 한다.

## 선택 가능한 방향

| 방향 | 사용자 경험 | 검토 사항 |
|---|---|---|
| 현재 자동 로그인 유지, 복구 안내 개선 | 가입은 닉네임만, 평소에는 바로 접속 | 가장 작은 변경. 복구 코드 보관 부담은 남는다. |
| 닉네임 + 이메일 인증 링크 또는 일회용 코드 | 기기를 바꿀 때 이메일로 인증 | 발송 제공자와 비용·제한, 토큰 만료·재사용 방지, 발송 실패 대응 필요 |
| 패스키 또는 신뢰할 수 있는 소셜 로그인 | 기기 인증 또는 기존 계정으로 로그인 | 기기 간 이용·분실 절차, 제공자 의존성, 기존 사용자 연결 방식 검토 필요 |
| 이름 + 생년월일만으로 복구 | 외우기는 쉬움 | 본인 확인 수단이 아니므로 채택하지 않는 것을 권장 |

## 복구 코드 제거 전 순서

1. 대체 인증 방식을 선택하고 기존 로그인 상태에서 새 인증 수단을 등록·검증하게 한다.
2. 사용자 ID를 유지한 채 새 인증 정보를 연결한다. 학습 기록, 구독, 일정은 같은 사용자에게 남긴다. 이름이나 생일이 같다는 이유로 계정을 합치지 않는다.
3. 세션이 없는 기존 사용자는 유예 기간 동안 현재 복구 코드로 계정 소유를 증명한 뒤 전환하게 한다. 코드도 없고 로그인된 기기도 없다면 이름·생일만으로 이전을 허용하지 않는다.
4. 새 기기 복구, 세션 만료, 중복 연결, 인증 제공자 장애, 로그아웃, 계정 분실 시나리오를 검증한다.
5. 실제 사용자의 이전을 확인한 다음 복구 코드 UI·API와 저장된 해시를 단계적으로 제거한다. 이전이 끝나기 전에 삭제하면 기존 사용자가 기록을 잃을 수 있다.

이번 작업에서는 검토 문서만 추가했다. 새로운 개인정보 수집, 외부 인증 서비스 연결, 운영 계정 변경 및 복구 코드 삭제는 하지 않았다.
