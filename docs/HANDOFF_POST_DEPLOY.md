- 이 인수인계 문서 및 이후 PROGRESS 기록은 로컬 변경이다. 이 세션에서는 추가 커밋/푸시/배포를 수행하지 않는다.

## 새 세션 시작 방법과 경계

1. AGENTS.md, docs/HARNESS.md, docs/REQUIREMENTS.md, 이 문서, docs/PROGRESS.md의 최신 기록을 읽는다. 제품 변경 전 하네스 계약을 따른다.
2. 사용자에게 배포 완료 여부와 실제 HTTPS 운영 URL을 받는다. 계정 비밀번호/API 키/DB URI를 채팅으로 요구하지 않는다. 환경변수는 이름과 설정 여부만 확인한다.
3. 처음에는 읽기 전용 상태 확인과 계획을 요약하고 사용자의 후속 지시를 기다린다. 이 새 세션 생성은 즉시 배포·재배포·푸시하거나 유료 호출을 시작하라는 지시가 아니다.
4. 운영 사용자 학습 기록과 음원을 초기화/덮어쓰기 하지 않는다. 실서비스 가입·답안 제출·복구는 사용자와 정한 검증 계정으로 수행하며 기존 실사용자 계정을 재사용하지 않는다.
5. 테스트는 격리 DB와 fake providers를 사용한다. 실제 제공자 검사와 운영 쓰기는 자동 테스트와 분리하고 목적/범위를 알린다. 실제 휴대폰 동작은 사용자 확인이 필요하며 데스크톱 에뮬레이션으로 대체 완료 처리하지 않는다.
6. 사용자가 직접 배포한다는 선택을 유지한다. 수정 완료 후 전체 검증과 변경 내역을 제공하고 다음 푸시/배포 범위를 확인한다. 원격 변경 없는 문서 준비/로컬 수정은 진행할 수 있다.

- RELEASE.md의 상위 체크 항목은 일부 이미 완료된 하위 작업을 묶고 있다. 키 발급·크레딧 충전·Atlas 이전·기존 30문항 검토를 다시 미완료로 안내하지 않는다.
- PROGRESS.md의 과거 'Git 저장소 아님', '플러그인 미설치', '테스트 환경 격리 미완료'는 당시 기록이다. 최신 2026-09-29 기록과 실제 상태를 우선한다.
- Vercel 배포 성공, 실제 cron 실행, 양쪽 휴대폰 알림은 아직 확인 증거가 없다.
- 로컬 백업에는 비밀값이 포함될 수 있다. 통째로 출력하거나 업로드하지 않는다.
