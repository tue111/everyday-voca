## 확인한 사용자 시나리오

- 이름 입력 → 복구 코드 보관 → 표현 목록 → 카드 → 10문제 제출 → 완료.
- 카드·퀴즈 진행 저장, 새로고침 후 이어하기, 다른 기기에서 코드로 복구.
- 오답·힌트 처리, 실패한 제출의 입력 보존과 재시도.
- 다음 날 복습 대상, 중간 새로고침, 복습 완료가 오늘의 새 표현 완료에 영향을 주지 않음.
- 같은 답안을 동시에 제출해도 실제 MongoDB에는 한 번만 저장.
- 서버를 다시 생성해도 DB·파일의 복구 코드와 진도 유지.
- 생성 작업 동시 실행, 최대 3회 시도, 예산 한도, 예비 콘텐츠 대체.
- 완료 사용자 알림 제외, 중복 발송 방지, 만료 구독 제거, 불확실한 실패 기록.
- Vercel 사전 파싱 본문·한국어 UTF-8 청크·요청 크기·출처 검사·비공개 캐시 정책.

## 발견·수정 기록

- 초기 의존성 누락 → lockfile 복구 및 캐시 기반 npm ci 재설치.
- Windows esbuild 상위 폴더 읽기 제한 → 허용된 일반 실행으로 검증.
- 긴 파일 생성 명령 제한 → 파일을 작은 단위로 나누어 작성.
- Vite 초기 변환으로 브라우저 30초 제한 초과 → 전체 학습 시나리오 제한을 120초로 조정; 검증 조건 유지.
- Vercel과 로컬 본문 처리 차이 → 두 형식 모두 지원하고 HTTP 테스트 추가.
- 테스트 임시 폴더 정리 → 경로 검증 후 정리하여 원래 오류를 덮지 않도록 수정.
- 음성 개선 검증 중 개발/브라우저 테스트 API 포트 충돌 → 테스트 API 포트 3002로 격리.
- Windows 로컬 JSON 교체 중 일시적인 EPERM → 원본을 삭제하지 않는 제한된 atomic rename 재시도 추가 및 테스트.
- 브라우저 디버깅 응답 본문이 오디오를 0바이트로 보고함(네트워크 전송은 8,044바이트) → 플레이어에 실제 전달된 Blob 크기 검증으로 변경. 빈 음원을 허용하도록 검증을 완화하지 않음.

- Atlas 연결로 서버 재시작 후 `/api/health`, `/api/app` 모두 HTTP 200 확인.
- 배포 업로드 제외 파일 `.vercelignore` 추가: 환경 설정·백업·사용자 데이터·검증 산출물 제외.
- 현재 대화에서 GitHub/Vercel 플러그인은 검색 결과 `installed:false`, 호출 가능한 작업 도구 없음. 실제 배포 미진행. 작업 폴더는 아직 Git 저장소 및 Vercel 프로젝트에 연결되지 않음.

## 배포 가능 여부 점검 (2026-09-26, 배포 미실행)

- 결론: 로컬 코드 검증 통과. Vercel 계정/프로젝트 연결과 운영 환경변수 준비 후 배포 가능한 구조이며, 실제 클라우드 빌드·실행 성공은 아직 미검증.
- Windows 샌드박스에서 esbuild 상위 폴더 읽기 제한으로 최초 검증 시작 실패. 일반 실행 환경에서 재검증.
- 기본 `npm run verify`는 HTTP 테스트 3개 실패: `server/runtime.ts`를 import할 때 `.env`를 읽고, 이후 beforeAll에서 테스트 모드를 설정해 실제 자격 증명 거부 조건에 걸림. 제품 코드·테스트 조건은 변경하지 않음.
- PowerShell에서 `$env:APP_MODE='test'`를 먼저 설정하고 `npm run verify` 실행: 종료 코드 0. 타입/ESLint, 단위·컴포넌트 35개, 격리 MongoDB 통합 7개, Playwright 7개, Vite 운영 빌드 통과. 기본 명령의 환경 격리 개선은 남은 하네스 보완 사항.
- `.env`에 설정된 비밀 값이 dist에 포함되는지 검사: 발견 0건. src/public/shared에서 서버 import 및 비밀 환경변수 참조 발견 없음.
- 실제 Atlas 읽기 전용 ping 성공(일반 로컬 네트워크). 데이터 변경 없음. Vercel에서의 Atlas 접근과 권한은 미검증.
- 로컬 MONGODB_URI/MONGODB_DATABASE/OPENAI_API_KEY는 설정됨. APP_URL/CRON_SECRET/VAPID_PUBLIC_KEY/VAPID_PRIVATE_KEY/VAPID_SUBJECT는 미설정. 값 자체는 출력하지 않음.
- `.vercel/project.json` 없음, Git 저장소 아님, PATH에서 Vercel CLI 미발견. 연결된 Vercel 도구의 팀 조회 결과는 빈 목록이므로 계정 측 프로젝트·환경변수·배포 권한 확인 불가. Git 저장소는 CLI 직접 배포의 필수 조건은 아님.
- 운영 준비: Vercel 로그인/접근 권한 확인 및 프로젝트 연결, Node 24/Vite/npm run build/dist 설정, Fluid compute 활성화 확인, 기존 DB·OpenAI 값의 서버 환경변수 등록, 정확한 HTTPS APP_URL 및 32자 이상 무작위 CRON_SECRET 설정. 알림 사용 시 VAPID 키와 연락처 설정. Atlas는 Vercel에서 연결할 수 있는 네트워크 접근 설정 필요.
- 공식 문서상 현재 Hobby는 프로젝트당 cron 100개/각 작업 하루 1회 및 시간대 내 실행을 지원. 현 cron 3개는 빈도 제한에 부합. Fluid compute의 Hobby 함수 최대 시간은 300초로 현 cron 설정과 부합.
  - https://vercel.com/docs/cron-jobs/usage-and-pricing
  - https://vercel.com/docs/functions/limitations
- 실제 배포, 원격 Vercel 빌드, 프로젝트/환경변수 변경, 유료 AI 호출, 실제 푸시, 실기기 검증은 수행하지 않음. 테스트는 가짜 AI/푸시/무음 WAV 및 별도 DB를 사용.
